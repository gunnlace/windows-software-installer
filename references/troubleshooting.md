# 安装故障排查、升级与回退

先收集最小事实：软件和版本、安装介质及来源、完整错误文字/代码、发生在哪一步、Windows 版本和系统类型、可用空间、是否已有旧版本或待重启的更新。让用户提供已隐藏账号、密钥和私人文件内容的截图或文字。

## 常见现象的诊断顺序

| 现象 | 先检查 | 安全处理 |
| --- | --- | --- |
| 无法运行/权限不足 | 发布者、UAC 画面、安装目录写入权限、组织策略 | 核验发布者后由用户确认提升权限；仍被策略拦截时找 IT。 |
| 双击安装包无反应 | 文件是否带来源标记、是否已损坏 | 按 [来源与签名](source-and-signature.md) 核对后解除锁定；哈希不符则重新下载。 |
| SmartScreen/安全软件拦截 | 官方来源、签名、哈希、警告原文 | 重新下载或找官方支持。 |
| 空间或路径错误 | 目标盘存在性、可用空间、临时空间、路径权限 | 使用默认或已确认的数据盘路径，避免改系统目录。 |
| 缺少 DLL/运行库 | 厂商系统要求、报错名称、软件版本 | 只从 Microsoft 或厂商官方渠道安装所需运行库。 |
| 许可证错误 | 授权类型、账号、服务器/网络要求、系统日期时间 | 不索取密钥；让用户联系许可证管理员或厂商。 |
| 版本/插件冲突 | 已装版本、兼容矩阵、正在运行的程序、待重启更新 | 不擅自卸载或覆盖；先确认影响与备份。 |

## 常见错误码对照

安装器报出的数字或十六进制代码大多来自 Windows Installer，含义相对固定。先按此表定位方向，再决定是否需要抓日志。

| 代码 | 通常含义 | 先尝试的安全处理 |
| --- | --- | --- |
| `1603` / `0x80070643` | MSI 安装失败的通用码，本身不指向具体原因 | 最需要抓日志的一类。常见诱因是旧版本残留、空间不足、待重启的更新、运行库缺失。先重启再试一次，再按下节抓日志。 |
| `0x80070005` | 拒绝访问，权限不足 | 以管理员身份运行安装程序；检查目标目录是否受组织策略或"受控文件夹访问"保护。不要取得所有权或改 ACL 强行继续。 |
| `1618` | 已有另一个安装正在进行 | 等待其他安装或 Windows 更新完成，重启后重试。不要强行结束 msiexec 进程，可能留下损坏的半安装状态。 |
| `1619` | 安装包无法打开 | 路径含特殊字符、文件不完整或已损坏。把安装包移到简单路径，重新下载并核对哈希。 |
| `1638` | 该产品的另一个版本已安装 | 先确认已装版本和是否需要保留；用厂商卸载器或"设置 → 应用"正常卸载，不要直接删目录。 |
| `2502` / `2503` | Windows Installer 调用权限异常，多见于双击 MSI | 改用管理员身份的命令提示符运行 `msiexec /i "路径.msi"`；也可检查 `C:\Windows\Temp` 权限是否被改动过。 |
| `1601` | Windows Installer 服务不可用 | 重启后重试；确认 Windows Installer 服务未被禁用。这通常是系统层面的问题，必要时找 IT。 |
| `0x80070570` | 文件或目录损坏且无法读取 | 下载不完整或介质有问题。重新下载并核对哈希；若来自 U 盘/移动硬盘，换介质再试。 |

## 抓取 MSI 详细日志

`1603` 这类通用码只能靠日志定位。让用户在管理员命令提示符中运行：

```
msiexec /i "D:\Downloads\安装包.msi" /l*v "D:\Downloads\install.log"
```

安装再次失败后打开 `install.log`，搜索 `Return value 3`。第一次出现的位置往上翻几行，通常就是真正的失败原因（缺少组件、路径不可写、前置条件不满足等）。让用户把这几行文字回报，不要要求上传整份日志——日志里可能含有用户名、路径和产品密钥。

`.exe` 形式的安装器日志位置由厂商决定，一般在 `%TEMP%` 下，具体文件名查厂商文档。

## 升级、卸载和回退

升级前确认新版本支持用户的 Windows、项目文件和插件，并保留能回退的安装来源、配置和数据备份。若安装器提示卸载旧版本、移除共享组件或覆盖项目数据，先把影响逐项告诉用户并等待确认。

卸载使用厂商卸载器或"设置 → 应用 → 已安装的应用"；先关闭软件，确认精确产品、用户数据的位置以及是否可恢复。不要推荐注册表清理器、批量删除目录或大范围磁盘清理。安装失败后的残留文件只有在官方文档明确要求且路径和可恢复性已确认时才处理。
