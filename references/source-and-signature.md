# 来源、签名与 SmartScreen

## 判断来源

官方下载页应与厂商身份和域名一致，使用 HTTPS，并清楚标明产品、版本、发布日期及 Windows 支持范围。搜索结果中的"广告""赞助"并不等同于厂商下载页。需要登录的客户门户、学校/公司软件中心可以是可信来源，但应由用户确认其组织归属。

选择安装包时，确认系统架构：多数普通 Windows 电脑使用 x64；ARM Windows 需要 ARM64；只有旧 32 位系统才选 x86。不确定时，在"设置 → 系统 → 系统信息 → 系统类型"查看，不能凭 CPU 品牌推断。

不要把搜索广告、第三方"高速下载器"或不明网盘链接作为默认来源。

## 核对数字签名

让用户在文件资源管理器中右键安装包，选择"属性"。若存在"数字签名"标签页，进入后选中签名者 → "详细信息"，核对两点：签名者名称与厂商是否一致，以及是否显示"此数字签名正常"。

没有"数字签名"标签页并不必然说明有问题（部分小型工具确实未签名），但此时哈希校验就成了唯一依据。

文件名、图标、扩展名或文件体积都不是可信度证明。不要要求用户把完整安装包上传到第三方在线扫描服务。

## 核对哈希

厂商公布 SHA-256 校验和时，让用户在 PowerShell（开始菜单搜索 "PowerShell"，无需管理员）中运行：

```powershell
Get-FileHash "C:\Users\用户名\Downloads\安装包.exe" -Algorithm SHA256
```

路径不要让用户手打。在文件资源管理器中，Windows 11 直接右键该文件；Windows 10 按住 Shift 再右键该文件，然后选择"复制为路径"。粘贴出的完整路径自带双引号，正好可直接放进命令中，无需删除。

把输出的 Hash 一列与官网公布值逐字符比对，大小写不影响。厂商公布的是 SHA-1 或 MD5 时，把 `-Algorithm` 换成 `SHA1` 或 `MD5`，但要说明这两种算法已不足以单独作为完整性依据，应结合签名和来源判断。

在 cmd 中的等价命令：

```
certutil -hashfile "C:\Users\用户名\Downloads\安装包.exe" SHA256
```

校验值不一致时，先重新从官网完整下载一次再比一遍——不完整的下载是最常见原因。第二次仍不一致，或签名失效、缺失且官网未作说明，停止安装。

## 文件被标记为"来自网络"（解除锁定）

现象：双击安装包毫无反应；提示"Windows 已保护你的电脑"；或解压出的便携版启动时报"拒绝访问"、找不到组件。原因是浏览器下载的文件被 Windows 附加了来源标记（Mark of the Web）。

**前提：只有在来源、签名或哈希已核对通过之后才做这一步。** 解除锁定等于告诉 Windows 你信任这个文件，顺序反了就失去了核对的意义。

单个文件：右键 → 属性 → "常规"标签页最底部。若出现"安全性：此文件来自其他计算机，可能被阻止…"一行，勾选右侧的"解除锁定"，点"应用"→"确定"。没有这一行，说明文件未被标记，不需要任何操作。

ZIP 压缩包要在解压之前先对 ZIP 本身解除锁定，否则解压出来的每个文件都会各自带上标记，逐个处理会非常麻烦。若用户已经解压完，可以用一条命令批量清除：

```powershell
Get-ChildItem -Path "D:\Apps\软件名" -Recurse | Unblock-File
```

运行前请用户确认这个路径下只有刚解压出来的、已核对过来源的文件，不要对整个磁盘或"下载"目录执行。

## SmartScreen 与安全软件

SmartScreen 或安全软件出现警告时，先停止并记录警告原文、发布者及文件来源。以下情形可以继续调查，但不能直接建议绕过：

- 文件来自厂商官网，签名、哈希和产品版本均能与官方记录对应；
- 厂商官方文档说明该版本可能触发信誉警告，并给出核验或更新路径。

优先重新从官网获取、检查日期与签名、更新安全定义或咨询厂商/组织 IT。若警告称文件已被篡改、恶意、签名无效，或来源无法确认，停止并不要运行。
